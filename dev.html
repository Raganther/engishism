How a point travels

Five steps, each owned by a different tier — no game does its own arithmetic. This section is prose, kept by hand (the payout code lives inside the engine, which this page deliberately does not load) — if it ever disagrees with hub-engine.js, the code is right.

1 · judgeThe round decides right or wrong — and is banned from knowing anything about points, which is what lets one round run in every game.
2 · recordKit.round.results (the shelf) writes down who got there, in what order, and how fast. The referee's notebook — it knows nothing about points either.
3 · worthThe skin contributes two facts and no maths: what the question is worth in its world (a tile's value, a hexagon = 1), and which payout rule it starts on. Bonus mechanics — the Daily Double, deductions, hint costs — are the skin's to have; their sizes are settings a teacher tunes.
4 · rulePAY_RULES (shared, written once each): winner-takes-all · podium · by-the-clock · everyone-equal. Takes the notebook plus the worth, hands back a number per team. A game switches rules from ⚙, never by code.
5 · payaward() is the one place a score actually changes — one cashier, so nothing can disagree. The team bar, the standings screen and the score report all only read; none of them calculate.

How one fix reaches everything

Two mechanisms. Both get called "sharing" and they solve opposite problems, which is why they are worth separate words.

registryA thing declares itself and the app finds it. Nobody keeps a list — the app loops over whatever registered, so a new round appears in the workshop menu, the settings panel, the content checker and this page at once. Cures the defect where a new thing must be threaded into nine places by hand and nothing complains when you miss one. Declare, don't special-case.
shelfA thing calls shared code. One copy of the behaviour, so mending it mends every caller — including rounds not written yet. Cures the defect where the same code sits in four files and drifts apart. Solve once, use anywhere. Run node tools/shelf.js to see what is on them.

When something moves onto a shelf: the first caller writes it inside itself — one caller is a guess about what the shared version should look like — and the second caller moves it and rewires both in the same change. The rewiring is what proves it is a shelf rather than a second copy under a new name.

Every tier has both. A game show declares itself to the game registry and calls Kit; a round declares itself to the round registry and calls Kit.round; a playground page calls BenchKit. What a round gets for free by existing is the whole phone layer — arming thirty handsets, reconnects, late joiners, per-team and per-player views. What it gets by asking is the team lanes, the agree rule, the reply readers and its own buttons. Nothing is automatic there: a round that never calls the lanes simply has none.

The shelf, and who calls it

Read from the source files when this page loads — the call sites themselves, not a drawing of them — so it cannot go stale. Rounds call the shelf to do their own work; hosts (the hub engine, the question bench) call it to drive a round they are showing. A row with one caller is a guess about an API rather than a shelf, which is the rule for when something is ready to be shared.

Skills — name it and the checklist loads

Type /name in Claude Code, or just describe the job — these open themselves when the work matches. Each one holds the traps that tier has already paid for. Descriptions are read from the skill files, so they cannot drift from what the skill says.

Commands worth keeping

Ask the code, never a list somebody typed — both of these read the registries, so a round or a helper added next month appears in them with nobody editing anything.

node tools/shelf.js            # every shared helper a round or a game can call
node tools/question-types.js   # every question shape content may be authored in

Before pushing. Match the check to what the change can break — a gate that always costs 25 minutes is a gate that gets skipped.

node tools/check-syntax.js                                        # seconds, always
NODE_PATH=$(npm root -g) node tools/smoke-test.js --only=content  # ~20s, any bank edit
NODE_PATH=$(npm root -g) node tools/smoke-test.js --only=qbench,grouping,card,gameshow
NODE_PATH=$(npm root -g) node tools/smoke-test.js                 # everything, ~25 min

Shipping. The stamp is found by search, never a list — and the 20YYMMDD shape is load-bearing, because classic.html carries ?v=picture and a looser pattern rewrites it into a broken page.

sed -i "s/?v=20[0-9]\{6\}[a-z]*/?v=$(date +%Y%m%d)a/g" $(grep -rl '?v=20[0-9]\{6\}' --include=*.html . | grep -v node_modules)
git add -A && git commit -m "..." && git push      # live in about 40 seconds
